# Manual

A small product documentation site with instant local search and a copy-page-as-Markdown button, so human readers and AI coding assistants both get clean context.

## Overview

Manual is a docs starter built on Astro's Starlight theme. It ships as a
complete, working documentation site for a fictional developer tool — Tapeline,
a webhook capture-and-replay CLI — so every page shows real docs writing: code
blocks with titled frames, option tables, callout asides, and cross-links. You
replace the sample content with your product's docs and keep the machinery.

The reader journey starts on a splash landing page with a hero, quick-link
cards, and an FAQ, then moves into a sidebar-driven docs area with three
groups (Start here, Guides, Reference) generated from the content file tree.
Site-wide search is Starlight's built-in Pagefind index, which returns
heading-level results — searching "exit codes" from any page jumps straight to
that section of the CLI reference.

The signature feature is Markdown portability: every docs page gets a
"Copy page as Markdown" button and a `.md` link beside its title, backed by
`/raw/<page>.md` routes that serve each page's source byte for byte. Pasting a
page into an AI assistant gives it the actual Markdown instead of scraped HTML.

## Features

- Splash landing page with gradient hero, original SVG terminal illustration,
  quick-link cards, and a four-question FAQ accordion that injects matching
  `FAQPage` JSON-LD from a single data file
- Five real documentation pages (getting started, configuration, two guides,
  CLI reference) with tables, titled code frames, and note/tip/caution asides
- Sidebar with three groups autogenerated from the `src/content/docs/` file
  tree, ordered by frontmatter, with mobile drawer navigation
- Built-in Pagefind full-text search on the built site, returning per-heading
  sub-results with anchor links
- "Copy page as Markdown" button on every docs page that puts the page's exact
  Markdown source on the clipboard, with Copied!/failed feedback states
- Raw Markdown endpoints at `/raw/<page>.md` for every page — predictable URLs
  AI tools can fetch directly
- Automatic light/dark theming with a custom cyan/teal accent palette and an
  original stroked-letterform SVG wordmark in both theme variants
- Fully static output: every route, including the raw Markdown files, works on
  direct load from any static host

## Tech stack

- **Language:** TypeScript
- **Framework:** Astro with the Starlight documentation theme
- **Build tool:** Astro
- **Styling:** Starlight CSS custom properties plus one custom stylesheet
- **Search:** Pagefind (bundled with Starlight, indexed at build time)
- **Linting:** ESLint

## Getting started

### Prerequisites

- Node.js 22 or newer
- npm

### Installation

```bash
npm install
```

### Development

```bash
npm run dev
```

Open the local URL printed by Astro.

## Available scripts

- `npm run dev` — start the local development server
- `npm run build` — type-check and create a production build
- `npm run lint` — run ESLint
- `npm run preview` — preview the production build locally

Search only works against the built site, so use `npm run build` +
`npm run preview` to try it. Astro's preview server runs in the background;
stop it with `npx astro preview stop`.

src/
├── assets/

│   ├── wordmark-dark.svg
│   └── wordmark-light.svg
├── components/
│   ├── FaqSection.astro
│   └── PageTitle.astro
├── content/
│   └── docs/
│       ├── guides/
│       ├── reference/
│       ├── start/
│       └── index.mdx
├── data/
│   └── faq.ts
├── pages/
│   └── raw/
│       └── [...slug].md.ts
├── styles/
│   └── theme.css

Docs pages live in `src/content/docs/` and become routes automatically.
`src/components/PageTitle.astro` is a Starlight component override that adds
the copy-as-Markdown actions, and `src/pages/raw/[...slug].md.ts` generates
the raw Markdown route for every page at build time.

## Personalizing

### Content and business data

Edit the Markdown files in `src/content/docs/` — `index.mdx` is the landing
page (hero title, tagline, actions, cards); `start/`, `guides/`, and
`reference/` hold the docs pages. Each page's frontmatter sets its `title`,
`description`, and `sidebar.order`. The FAQ questions and answers live in
`src/data/faq.ts` and feed both the landing-page accordion and the JSON-LD.
The site title, description, and sidebar group labels live in
`astro.config.ts`; set `site` there to your real docs URL before deploying.

### Branding and styles

Edit `src/styles/theme.css`. The two blocks at the top define the accent and
gray palettes for dark and light themes via Starlight's CSS custom properties;
the hero gradient, landing glow, and card accent overrides follow in the same
file. Typography is Starlight's default system font stack on purpose.

### Images

All artwork is original SVG. The header wordmark is
`src/assets/wordmark-light.svg` and `wordmark-dark.svg` (referenced from
`logo` in `astro.config.ts`; keep roughly a 200 × 34 viewBox so the header
height fits). The landing illustration is `src/assets/terminal.svg`,
referenced from the hero in `src/content/docs/index.mdx`. The favicon is
`public/favicon.svg`.

### Routes and features

Routes mirror the `src/content/docs/` file tree; add a Markdown file to add a
page, and the sidebar groups in `astro.config.ts` pick it up automatically
(`autogenerate` per directory). The copy-as-Markdown button lives in
`src/components/PageTitle.astro`; the raw Markdown endpoints in
`src/pages/raw/[...slug].md.ts`; the FAQ renderer and JSON-LD injection in
`src/components/FaqSection.astro`. Search needs no configuration — Starlight
indexes the site with Pagefind on every build.

### Environment variables

This project does not require environment variables.
